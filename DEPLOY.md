# ПТН ПНХ — деплой у Telegram (крок за кроком)

Гра складається з двох частин:

| Частина | Що це | Де хоститься |
|---|---|---|
| `game/` | HTML5-гра (index.html + assets/) | Статичний хостинг, напр. **GitLab Pages** |
| `bot/`  | Node.js-сервер бота (тримає токен, викликає `setGameScore`) | Сервер, що постійно працює — напр. **Render.com** |

GitLab Pages не вміє запускати серверний код і не може безпечно зберігати токен бота, тому боту потрібен окремий хостинг. Гра ж — це просто статичні файли.

---

## Крок 1. Створити бота і гру через @BotFather

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot`, дайте імʼя. Збережіть виданий **токен**.
2. `/mybots` → ваш бот → **Bot Settings → Inline Mode → Turn on** (гра працює через inline-механізм).
3. `/newgame`:
   - Оберіть бота.
   - Введіть назву гри, опис, завантажте зображення (та відео, опційно).
   - Введіть **short name** (латиницею, напр. `ptn_pnh`) — воно піде в `GAME_SHORT_NAME`.
   - URL гри BotFather запитає пізніше не тут — його ви вкажете в коді бота (крок 3).

---

## Крок 2. Викласти гру на GitLab Pages

У папці `game/` вже лежить `index.html`, `assets/` і готовий `.gitlab-ci.yml` — GitLab на відміну від GitHub не публікує гілку напряму, а вимагає CI-джобу з назвою `pages`, яка складає сайт у папку `public/`. Цей файл уже все робить сам, нічого додатково писати не треба.

```bash
# у папці game/ вже лежить index.html + assets/ + .gitlab-ci.yml
cd game
git init
git add .
git commit -m "PTN PNH game"
git branch -M main
git remote add origin https://gitlab.com/ВАШ_НІК/ptn-pnh-game.git
git push -u origin main
```

Після push GitLab автоматично запустить пайплайн (**CI/CD → Pipelines** в інтерфейсі проєкту — можна спостерігати процес наживо). Коли джоба `pages` позеленіє, зайдіть у **Settings → Pages** — там зʼявиться посилання на сайт, зазвичай такого вигляду:

```
https://ВАШ_НІК.gitlab.io/ptn-pnh-game/index.html
```

(Якщо проєкт створено у групі, адреса буде `https://ВАШ_НІК.gitlab.io/ГРУПА/ptn-pnh-game/index.html`.)

Перше розгортання може зайняти кілька хвилин; наступні деплої після кожного `git push` — швидші.

Це і є ваш `GAME_URL`.

## Крок 3. Налаштувати й задеплоїти бота (Render.com, безкоштовно)

### 3.1. Реєстрація
Зайдіть на [render.com](https://render.com) → Sign Up → увійдіть через GitHub чи GitLab (той сервіс, куди ви запушили `bot/`). Render попросить дозвіл читати ваші репозиторії — це нормально. Безкоштовний акаунт не вимагає картки для Web Service.

### 3.2. Створення Web Service
На дашборді → **New → Web Service** → оберіть репозиторій із `bot/`.

- Якщо `bot/` — підпапка в тому ж репозиторії, що й гра (а не окремий репо), обовʼязково вкажіть **Root Directory: bot** — інакше Render шукатиме `package.json` у корені й не знайде його.
- **Name**: будь-яке (напр. `ptn-pnh-bot`) — стане частиною URL.
- **Region**: найближчий до вашої аудиторії.
- **Branch**: main.
- **Environment**: Node.
- **Build Command**: `npm install`
- **Start Command**: `npm start`
- **Instance Type**: Free (достатньо для тестування й невеликого навантаження).

### 3.3. Змінні середовища
У розділі **Environment** налаштувань сервісу натисніть **Add Environment Variable** і додайте кожну зі змінних `bot/.env.example` окремо:

| Змінна | Звідки взяти |
|---|---|
| `BOT_TOKEN` | Токен від @BotFather (крок 1) |
| `GAME_SHORT_NAME` | Short name, вказаний у `/newgame` (крок 1) |
| `GAME_URL` | Посилання на задеплоєний `index.html` гри (крок 2) |
| `SIGNING_SECRET` | Згенеруйте: `openssl rand -hex 32` |

`PORT` можна не додавати — Render сам підставляє порт через змінну середовища, а `server.js` вже читає `process.env.PORT` з фолбеком на 3000.

**Ніколи не вставляйте ці значення в код чи в git** — тільки сюди, в Environment.

### 3.4. Перший деплой
Натисніть **Create Web Service**. На вкладці **Logs** видно збірку в реальному часі: `npm install`, потім `npm start`. Успіх — рядок `PTN-PNH bot server listening on :10000` (чи інший порт) і зелений статус **Live** угорі. Перший деплой займає 2-5 хвилин.

### 3.5. Перевірка
Render видасть публічний URL, напр. `https://ptn-pnh-bot.onrender.com`. Відкрийте `https://ptn-pnh-bot.onrender.com/health` у браузері — має повернути `{"ok":true}`. Якщо ні — дивіться Logs.

### 3.6. Вебхук

Скажіть Telegram надсилати оновлення на ваш сервер:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://ptn-pnh-bot.onrender.com/webhook"
```

Успішна відповідь: `{"ok":true,"result":true,...}`. Перевірити стан вебхука будь-коли:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"
```
— там видно ваш URL і чи були помилки доставки (`last_error_message`).

### 3.7. Особливість безкоштовного плану
Сервіс **засинає після ~15 хв без запитів** і "прокидається" за 30-50 секунд на перший запит. Перший `/play` після паузи може здатись підвислим — це нормально, не баг. Якщо потрібна миттєва відповідь завжди — платний план "Starter" (~$7/міс) прибирає засинання.

### 3.8. Подальші оновлення
Кожен `git push` у main автоматично тригерить новий деплой (видно в Logs: "Deploying" → "Live"). Зміну змінних середовища теж треба зберегти кнопкою **Save Changes** — сервіс перезапуститься сам, без потреби пушити код.

## Крок 4. Прописати SCORE_ENDPOINT у грі

У `game/index.html` знайдіть рядок:

```js
const SCORE_ENDPOINT = 'https://YOUR-BACKEND-URL.example.com/api/score';
```

і замініть на реальний URL бота, наприклад:

```js
const SCORE_ENDPOINT = 'https://ptn-pnh-bot.onrender.com/api/score';
```

Закомітьте й запуште зміну — GitLab автоматично перезапустить пайплайн і оновить Pages.

## Крок 4.5. Відродження: поширення і винагороджувана реклама (опційно)

На екрані «Mission failed» тепер два способи відродитись із одним щитом, по черзі:

1. **Перший провал** — кнопка **«📤 Share with a friend · +1 shield»**. Відкриває діалог поширення Telegram (`t.me/share/url`) з посиланням на гру. Оскільки Telegram не дає callback «повідомлення реально надіслано», нагорода видається за стандартною евристикою «share-to-unlock»: коли гравець повертається у застосунок після відкриття вікна поширення (подія `visibilitychange`/`focus`).
2. **Другий провал** (в тому ж забігу) — кнопка **«▶ Watch ad · +1 shield»** через [Adsgram](https://adsgram.ai), рекламну мережу, спеціально створену під Telegram Mini Apps.
3. **Третій провал** — гра завершується остаточно, жодних кнопок відродження.

### Налаштування посилання поширення
У `game/index.html` знайдіть:
```js
const SHARE_URL = 'https://t.me/YOUR_BOT_USERNAME';
```
і вставте публічне посилання на вашого бота (те, що видав BotFather).

### Налаштування реклами (Adsgram)
Поки `AD_BLOCK_ID` в `game/index.html` не налаштований, кнопка автоматично показує **симуляцію реклами** (3-секундний таймер) — можна тестувати весь флоу без реального акаунту.

Щоб увімкнути справжню рекламу й монетизацію:
1. Зареєструйтесь на [adsgram.ai](https://adsgram.ai) як власник застосунку.
2. Створіть рекламний блок (Ad block) типу **Rewarded**, вкажіть посилання на вашого Telegram-бота.
3. Скопіюйте виданий **Block ID**.
4. У `game/index.html` знайдіть рядок:
   ```js
   const AD_BLOCK_ID = 'YOUR-ADSGRAM-BLOCK-ID';
   ```
   і вставте свій ID.
5. Задеплойте оновлений файл — симуляція автоматично зникне, і кнопка почне показувати реальну рекламу.

Кількість відроджень за забіг регулюється змінною `revivesUsed` у `game/index.html` (зараз максимум 2: поширення → реклама) — за потреби можна додати ще кроки в `gameOver()`.

## Крок 5. Перевірка

1. Напишіть своєму боту `/play` в особистих повідомленнях.
2. Прийде повідомлення-гра з кнопкою **Play**.
3. Натисніть — відкриється WebView з вашою грою (з `user_id`, `chat_id`, `message_id`, `sig` у параметрах URL).
4. Пройдіть раунд, програйте — рахунок автоматично піде на `/api/score` → бот викличе `setGameScore`.
5. Щоб побачити таблицю лідерів, викличте (наприклад, тимчасовим debug-запитом) `getGameHighScores` або просто пограйте кількома акаунтами — Telegram сам покаже "🏆 X гравців" під повідомленням гри.

## Нотатки з безпеки

- **Ніколи** не кладіть `BOT_TOKEN` у `game/index.html` чи будь-де на клієнті — тільки в `bot/.env` на сервері.
- Підпис (`sig`) у URL гри не дає підробити рахунок для чужого `user_id`/чату — `/api/score` перевіряє HMAC перед викликом `setGameScore`.
- `force: false` у `setGameScore` означає, що новий рахунок не перезапише вищий попередній — це стандартна поведінка для чесного лідерборду.

## Що можна покращити далі

- Додати `getGameHighScores` ендпоінт у бота, щоб показувати топ прямо в грі (не тільки в чаті Telegram).
- Розділити хвилі/рівні на іменовані (напр. "Хвиля 1: розвідка", "Хвиля 4: бронетехніка") для більшої драматургії.
- Додати мобільну вібрацію (`tg.HapticFeedback.impactOccurred`) при влучанні.
